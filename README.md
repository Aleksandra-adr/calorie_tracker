# Трекер калорий

Учебный проект: учёт приёмов пищи (продукт, вес, дата, калории, БЖУ), расчёт и агрегация
по дню/неделе, веб-форма и повторяемый workflow дневного отчёта.

Собран для ДЗ №2 («Агенты · Workflow · Изоляция»): работа разбита на четыре независимые
зоны и выполнена **четырьмя параллельными субагентами в одной сессии**, каждый — в своей
папке, без права трогать чужие. Подробности, конфликты между зонами и то, что не получилось
с первого раза — в [REPORT.md](REPORT.md).

## Структура

| Папка | Зона | Агент |
|---|---|---|
| `models/`, `storage/`, `api/` | данные и API | A |
| `calculations/`, `tests/test_calculations.py` | расчёты и property-тесты | B |
| `frontend/` | веб-интерфейс | C |
| `workflows/` | дневной отчёт (workflow) | D |

## Как запустить

### 1. Установить зависимости

```bash
pip install -r requirements.txt -r requirements-calculations.txt
```

### 2. Запустить API

```bash
uvicorn api.main:app --reload
```

API поднимается на `http://localhost:8000`. База SQLite создаётся автоматически
в `storage/calorie_tracker.db` при первом запуске (путь переопределяется переменной
`CALORIE_TRACKER_DB`). Контракт эндпоинтов — [api/API_CONTRACT.md](api/API_CONTRACT.md).

### 3. Открыть фронтенд

```bash
cd frontend
python -m http.server 8532
```

Открыть `http://localhost:8532/index.html` в браузере (API должен быть запущен на
`http://localhost:8000` — константа `API_BASE_URL` в `frontend/app.js`). Страницу можно
открыть и прямо из файла (`file://`) — она не разваливается без backend, просто показывает
баннер об отсутствии соединения.

### 4. Прогнать тесты расчётов

```bash
pytest tests/test_calculations.py -v
```

17 тестов (12 unit + 5 property-based на hypothesis), все зелёные.

### 5. Запустить дневной отчёт (workflow)

```bash
python workflows/daily_report.py --source api --api-base-url http://localhost:8000 --date 2026-08-24
```

Повторный запуск с теми же данными даёт статус `unchanged` и не переписывает файл —
подробности в [workflows/DEPENDENCIES_ASSUMED.md](workflows/DEPENDENCIES_ASSUMED.md).

## Что проверено вживую координатором

- `pytest tests/test_calculations.py` — 17/17 passed.
- Поднят реальный API (`uvicorn`), через `curl` пройден цикл create/list.
- `workflows/daily_report.py --source api` запущен дважды подряд на реальном API:
  первый раз `recomputed`, второй — `unchanged`, числа идентичны.
- Фронтенд открыт в браузере поверх реального API: добавлены две записи через форму,
  таблица и итоговая строка за день посчитались верно, консоль без ошибок.

## Кто что делал

Всё сделано одним человеком через четыре параллельных субагента Claude Code в рамках
одной координирующей сессии (роль — разработка). Разбивка на зоны, дозадание, сведение
контрактов и итоговая интеграционная проверка — координирующей сессией (главным агентом).

## Workflow

Обязательный по заданию workflow — [workflows/daily_report.py](workflows/daily_report.py):
взять приёмы пищи за сегодня → посчитать итоги → сравнить с нормой → сохранить сводку
в `workflows/output/<дата>.{json,md}` → идемпотентно пометить как выполненное (хэш от
входных данных). Запускается повторно с предсказуемым результатом — проверено дважды
подряд на трёх источниках данных (mock, storage, живой API).
